# インストールと更新

開発者が更新・整理・インストーラー検証を行う際は、[必須ファイル保持検証](preservation-checks.md)を必ず実施する。設定・DBなどが作業前から欠落していても失敗とし、存在するファイルだけの比較を成功根拠にしない。

## 版番号訂正後の移行

ユーザー指定で旧v0.4.0をv0.1.2へ再採番し、旧v0.2.0/v0.3.0のReleaseとタグは撤回しました。v0.1.3はその後のパッチ版です。ユーザーが旧版をアンインストールしてから新規導入するため、旧番号導入状態からの上書き移行は対象外です。破壊的変更は許容されています。通常の自己更新・インストーラーの版比較は維持します。

## Windows x64への導入

配布されている `TranscriptionServer-v<バージョン>-setup-x64.exe` を実行します。発行元が KotorinChunChun であることと、配布元のSHA256SUMS.txtとの一致を確認してください。この開発者署名を発行元として信頼しているPCでは、Windowsが署名の有効性を検証できます。既定のプログラム先は %LOCALAPPDATA%/Programs/TranscriptionServer です。ユーザー単位で管理者権限なしに導入します。

本体はRust EXE。配布物にはPython/Whisper、NeMo-Speech.cpp、speech.cpp、FFmpeg/FFprobe、モデル重み、CUDAを含めない。管理画面から必要な実行環境を専用領域へオンライン導入し、サーバー再起動後にモデルを導入する。Pythonを導入するのはWhisper専用ワーカーだけで、PCのPython/PATHは変更しない。起動時の点検結果に未準備の理由を表示する。

## 旧Python版からの移行

ユーザー指定でv4.1.0/v4.2.0からRust版v0.1.0へ番号を変更した。この初回はインストーラーで移行する。同じAppIdと保存先を維持し、Rust世代へ移行する今回の番号変更だけを許可する。通常の旧版上書き禁止は維持する。

既存の録音処理を完了/中止して終了し、DBと設定をバックアップする。インストーラーは確認済みの旧BUILD.jsonを基に旧Pythonサーバー用_internalとPython更新ヘルパーを整理し、Rust本体＋Whisper専用ワーカーを配置する。録音・字幕・設定は削除しない。旧バイナリとソースは過去のGitHub Releaseに残す。

## 保存先

| 内容 | 既定の位置 |
| --- | --- |
| プログラム | %LOCALAPPDATA%/Programs/TranscriptionServer |
| 設定 | %LOCALAPPDATA%/TranscriptionServer/settings.json |
| 録音・字幕・SQLite | %LOCALAPPDATA%/TranscriptionServer/data |
| 更新取得/記録/バックアップ | %LOCALAPPDATA%/TranscriptionServer/updates |

明示した--data-dirは継続し、旧DBが旧保存先にだけある場合は引き継ぐ。既存DBのjobs/segments/job_indexのJSONとIDを保持する。プロセス再起動で途中の推論を再開したふりはせずinterruptedにし、確定字幕を保持する。アンインストールでもデータ・設定・資格情報・更新バックアップを残す。

## 更新確認と適用

「設定・更新」の「更新を確認」で公開リリースを確認する。更新元はアプリ内部で固定されており、トークンの入力やサインインは不要。旧版が保存した認証情報は更新に使わない。

導入版は起動5秒後と24時間ごと、または手動で更新を確認する。Rust世代を示すReleaseだけを比較し、旧Python v4系を数値の大小で誤選択しない。draft/prerelease/同版/旧版は適用しない。

利用者が確認画面で適用した時にだけ取得・再起動する。転送/認識中は拒否し、適用直前は新規受付を止める。公開インストーラーをHTTPSで取得し、配布ホストを制限して、サイズとSHA-256を照合する。

Rust本体EXEをアプリ外の更新キャッシュへコピーし、独立したヘルパーとして起動する。親PID/開始時刻/終了状態と承認引き継ぎを照合し、プログラムとSQLiteをバックアップする。サイレント適用後に同じ引数で起動し、healthのappId/版/実PIDを確認する。更新ヘルパーにPythonは使わない。

v0.1.18以前から更新する場合は、署名済みインストーラーを使います。公開リリースのトークン不要の更新確認には v0.1.19 以降が必要です。

## 失敗と復旧

last-handoff.jsonが示す更新フォルダーのresult.json、install.log、error.logを確認する。適用/起動に失敗した場合は所有プロセスを終了してプログラムを旧版へ戻す。DBを古いスナップショットで自動上書きしない。復旧にも失敗した場合はバックアップを保持して手動で確認する。

復旧先は導入marker/BUILDで照合し、プログラムのリンク先や無関係なフォルダーを再帰削除しない。更新バックアップは自動削除しない。将来DBを破壊的に変更する版は、別途移行/後方互換の設計が必要。

## 配布

コミット済みソースからRust本体・同梱Web画面・Inno SetupとZIP/ハッシュを作る。非公開draftで候補を保存して試験し、ソース/タグをpushした後に安定Releaseへ変更する。正式なRust ReleaseをLatestへ設定し、過去版は上書きしない。録音・DB・モデル・PC専用台帳・認証情報は含めない。

## v0.1.7の既存導入への適用

配布物を軽量化しても、既存の実行環境やモデル保存先を削除しない。以前の同梱worker/runtimeフォルダーが導入先に残っている場合は従来の検出を継続する。既存フォルダーを削除して軽量化する操作は含めない。個別アプリの同梱起動は専用instance-id/loopback/ポート/設定/データ/PID記録を指定し、共有サービスの--installedを使用しない。

## v0.1.14作り直し版・インストール後の接続案内

インストール完了画面で「サーバーを起動してクライアント接続方法を表示」を選択すると、初期準備中でも接続案内が開きます。案内はサーバーが通知するLAN URL、接続キーの要否、準備状態を表示します。管理画面上部の「接続方法」またはスタートメニューの「クライアント接続方法」から再表示できます。

スタートメニューのTranscriptionServerはサーバーを起動して管理画面を開きます。デスクトップの同じショートカットは新規導入時に既定で選択され、不要なら解除できます。更新時はInno Setupの既存タスク選択が保持される場合があります。起動済みの導入版では管理画面を開き、2つ目の共有サーバーを起動しません。PC起動時の自動起動は設定しません。

接続方法ショートカットとインストール後の起動は--installed --connection-guide、通常起動は--installed --openです。--no-browser指定時は接続案内も自動表示しません。サイレントインストールは従来どおり起動・ブラウザー表示を行いません。接続案内は管理画面の?guide=1で表示できます。
