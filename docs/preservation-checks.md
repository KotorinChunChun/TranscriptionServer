# 更新・整理の必須ファイル検証

設定が作業前から欠落している場合も失敗です。「前後とも不存在」「存在するファイルだけのSHA一致」は保持成功にしません。欠落を見つけたら操作を開始せず報告し、復元は別途承認された復旧作業として扱います。

## 必須の順序

1. 対象インスタンスの明示された設定先・データ先・プログラム先を確定する。`settings.json`、`workbench.sqlite3`、`TranscriptionServer.exe`、`BUILD.json`、`INSTALLATION.json`を必須とする。正式導入の受入ではインストール登録も確認する。
2. 維持する録音・モデル・その他設定の実ファイル/フォルダーを明示する。存在するものを列挙するだけでは、最初から欠落したファイルを検出できない。保持モデルごとの重み・設定ファイルを`--keep-file`で必須にする。不要モデルの除外は承認された対象だけにする。
3. 操作の承認とジョブ完了・停止を確認し、書込みが止まった状態で退避と基準記録を作る。DBのSHA比較は稼働中に実施しない。停止やバックアップ取得をこのツールが自動で行うことはない。
4. 共通スクリプトで事前検証する。失敗時はsetup適用・削除・成功記録へ進めない。PowerShellでは外部コマンド失敗が自動停止しないため、必ず`$LASTEXITCODE`を確認する。
5. 作業直前にも基準との差分を確認する。整理では全削除候補が保持対象・必須ファイル・その親やリンク別名を含まないことを確認する。別途、承認済み範囲、リンク、稼働プロセスも検査する。このツールは削除の許可や実行を行わない。
6. 作業後に基準を読み直して存在・SHA256を確認する。空/旧形式/必須対象が欠けた基準は拒否する。設定の変更が必要なら変更予定項目と別の照合を定義し、元の基準を上書きして成功にしない。
7. 更新後のEXE/BUILD/INSTALLATIONは存在・可読性を確認し、内容は新配布物とのSHA・版・登録先の独立照合を行う。新規インストール候補では初回起動後に設定・DBが生成されたことを必須確認する。正常な新規導入と既存設定の消失を混同しない。

## 共通コマンド

開発環境のPython 3.12以上で実行する検証ツールです。製品へ追加Pythonを同梱する変更ではありません。以下の変数は対象ごとの絶対パスへ設定し、監査記録は非公開・Git管理外へ保存します。設定値や秘密鍵の内容は記録しません。

```powershell
# $python, $guard, $program, $settings, $data, $modelFile, $baseline は対象ごとに設定する。
& $python $guard capture --mode update --program-dir $program --settings-file $settings --data-dir $data --keep-file $modelFile --keep-tree $data --output $baseline
if ($LASTEXITCODE -ne 0) { throw '必須ファイルの事前検証失敗。作業中止。' }
& $python $guard verify --manifest $baseline --before-operation
if ($LASTEXITCODE -ne 0) { throw '事前状態が変化。作業中止。' }
# ここで承認済みの更新を実行する。
& $python $guard verify --manifest $baseline
if ($LASTEXITCODE -ne 0) { throw '保持検証失敗。成功扱いにしない。' }
```

`$guard`はリポジトリの`scripts/preservation.py`です。整理は`--mode cleanup`で基準を作り、削除直前に以下も必須です。`$targets`は今回承認された削除候補の絶対パス配列を保存したJSONです。

```powershell
& $python $guard check-targets --manifest $baseline --targets $targets
if ($LASTEXITCODE -ne 0) { throw '削除候補の検証失敗。削除禁止。' }
```

`update`では設定・DB・追加保持対象のバイト不変を確認し、`cleanup`ではプログラム本体も不変を確認します。取得前の必須ファイル欠落、JSON破損/空設定、アクセス拒否、保持フォルダー欠落/空、取得後の消失をすべて失敗にします。基準ファイルは新規作成のみです。ツール成功だけでジョブ整合性・API動作・証明書・全モデルの動作まで確認済みとは扱いません。

## 過去の検証の訂正

2026-11-14のv0.1.12候補setup検証と容量整理では、通常設定の欠落を除外したため保持確認が不十分でした。候補の新規/更新試験そのものと、通常設定の保持確認を分けて扱います。過去の結果JSONは当時の記録として維持し、設定保持の成功根拠として再利用しません。完了済み整理スクリプトは実行を拒否するように変更しました。新しい整理では新しい基準を作成してください。

v0.1.13からWindows配布/インストーラーにも`scripts/preservation.py`を同梱しています。管理者が明示実行する開発・保守用の検証ツールです。インストーラーやRust自己更新ヘルパーが自動実行する機能ではなく、サーバー本体へ追加Python依存は導入していません。
