# 実行環境とモデルの管理

Web画面は管理専用です。サーバー更新の確認・適用とGitHub読取接続の設定・解除は、右上の「設定・更新」ポップアップに集約しています。更新管理のサーバーPC限定と既存の認証は維持します。以下の「起動時の準備・容量表示」はv0.1.12の仕様です。v0.1.11以前の稼働版への適用は別操作です。

## 起動時の準備・容量表示（v0.1.12）

初回起動時にWhisper専用環境、speech.cpp、NeMo-Speech.cpp、FFmpeg/FFprobeを点検し、不足分を1種類ずつオンライン導入します。正常な既存環境は再利用します。準備中も管理HTTPとPID記録を提供しますが、認識の新規受付は止めます。取得・SHA256検証・展開・起動点検後に同じプロセスで配置を再検出し、認識受付を開始します。手動再起動は不要です。初回公開のv0.1.14まではモデル本体の自動取得・ロードは行いません。作り直し版は後述の初期モデルを取得します。一体型も既定無効で、明示有効化した隔離環境でのみ今回の実行検証を行います。

準備中はCLIと管理画面に対象・進捗を表示します。healthのstartupState=preparing、acceptingJobs=falseで準備中を識別できます。自己更新の起動判定は管理HTTPの対応版/PID応答を確認するため、モデル未準備と起動失敗を混同しません。導入失敗でも残りへ進み、失敗した環境だけ管理画面から再導入/修復できます。成功した部品はその場で反映し、手動再起動しません。次回起動も不足分だけを再試行します。破損した外部指定は上書きしません。中止ボタンは準備を中止し、同PCの停止APIとCtrl+Cはサーバーを終了できます。オフライン/開発用の`--no-auto-runtimes`と導入版の`"auto_install_runtimes":false`も維持します。

管理画面の「実行環境」を開くと4種類の状態と容量を確認できます。合計は管理対象の現行配置と既知の同梱配置の**論理ファイル容量**です。モデル・キャッシュ・旧版退避・展開用一時領域は含みません。リンク先は走査せず、同じパスは重複加算しません。外部指定の任意フォルダーを丸ごと走査しないため、外部配置・読取不能などは「一部未集計」、合計は「集計済み」と表示します。外部配置を0バイトと断定しません。実ディスク使用領域やRAM/VRAMとは異なります。容量は30秒キャッシュし、再点検で更新します。

4種を新規導入する参考容量は788,060,917バイト（0.788GB）、取得量は287,143,787バイト（273.8MiB）です。これは固定パッケージの参考値で、既存の外部環境・旧同梱環境の実使用量ではありません。モデル本体・GPUドライバー・追加CUDA/cuDNNは別です。

## 管理画面

モデルは用途別の一覧表で表示します。「モデル」「保存容量」の表見出しで昇順/降順を切り替えます。簡易表示はモデル名・保存容量・RAM/VRAM最大概算・参考速度/フィラー・操作を表示し、狭い画面では容量類をモデル名の下へまとめます。状態列は設けず、導入/削除の活性状態と背景色で区別します。詳細表示は用途解説・計算時間・精度・RAM/VRAMの範囲と根拠・資料なども表示し、簡易用の略式容量は重ねて表示しません。

常駐対応モデルの操作欄には「ファイル処理」「リアルタイム」の各行へCPU/GPU/アンロードを並べます。導入データは共通で、枠ごとにメモリ常駐を切り替えます。一覧の種類や並び順を切り替える操作ではありません。認識ごとに自動ロード・解放するモデルには常駐操作を表示しません。

モデル一覧の「導入」は、不足する実行環境があればそれを先に取得し、続けてモデル本体を取得します。起動時の自動準備とは異なり、利用者によるモデル取得の明示操作です。正常な実行環境は再取得しません。実行中の新規導入/修復も受付停止中にそのまま反映し、必要な旧常駐ワーカーを解放します。モデル本体の取得だけなら再起動不要です。途中失敗・中止でも導入済みの部品と再起動の必要性を画面へ反映します。

「導入を確認」は廃止し、導入状態の点検は上部の「モデルを再点検」へ集約しています。「削除」は保存ファイルを削除する操作です。アンロード（メモリ解放）とは異なります。両処理枠から解放して確認画面で承認したモデルだけが対象です。処理・待機・転送・更新・他の管理操作中は拒否します。

削除APIは`POST /api/management`へ`{"action":"delete","model":"whisper/tiny","confirm":"delete-model"}`を送ります。固定モデルIDのみ許可し、Whisperは実際に使用するHFキャッシュ内の固定モデルリポジトリー、Nemotron ASRは専用の重み1ファイル、speech.cppは固定名の`rm NAME`を使います。録音・字幕・設定・実行環境・他モデルは保持します。削除後に使う場合は再導入が必要です。この変更はv0.1.9の配布物に含まれます。既存の稼働版へはインストーラー適用後に反映します。

管理画面には不足警告を表示し、モデル一覧の「導入」から必要な実行環境とモデルをサーバーPCへ導入します。既存の信頼LAN・操作トークンを使い、キーの手入力を追加要求しません。処理・転送・更新・他の管理操作と競合する場合は拒否します。

v0.1.8では、ファイル検出と起動点検を区別し、壊れた環境や未対応モデルも一覧へ残します。管理対象の壊れた環境には「修復」を表示し、固定SHA/展開/起動の検証後に旧フォルダーを`.previous-*`へ退避して交換します。失敗時は旧配置へ戻し、退避は自動削除しません。録音・モデルは変更しません。明示設定した外部配置は自動修復せず、パス/ライブラリを案内します。

v0.1.12は起動時準備も実行中の再導入/修復も同じプロセスに反映します。反映中のロード/認識は拒否します。公開v0.1.11以前では再起動が必要です。PCの再起動は不要です。導入状態を取得できない場合は「未確認」と表示し、未導入と推測して導入を求めません。

| 対象 | 固定版 | 取得上限 | 導入内容 |
| --- | --- | --- | --- |
| Whisper専用環境 | faster-whisper 1.2.1 / CPython 3.14.10 x64 | 130MiB（実取得119.6MiB） | 専用埋込Python・固定24 wheels・アプリ内C++依存DLL・ライセンス |
| speech.cpp | 0.10.1 | 50MiB | 旧ネイティブASRとVAD/話者分離のCLI・DLL・同梱資料 |
| NeMo-Speech.cpp | 0.3.0 | 30MiB | Nemotron 3.5 ASR用のCLI・CPU/Vulkan DLL・model-index・ライセンス |
| FFmpeg / FFprobe | Gyan Essentials 8.1.2 | 160MiB | 音声・動画変換/点検CLI・同梱資料 |

実行環境は最大約1.3GBの展開用空きを確認してから取得を開始します（モデルの空き容量は別途必要です）。HTTPS固定URLと組込みSHA256、ZIPの容量/パス/重複/リンク、実行ファイルの起動と版を検証し、すべて通過してから完成品へ切り替えます。進捗・中止・失敗理由を管理画面に表示します。実行環境単体の導入APIにモデル重みは含めませんが、モデル一覧の「導入」は続けて必要な重みも取得します。GPUドライバー、CUDA/cuDNNは取得しません。Pythonを取得するのはWhisper専用環境だけで、PCのPythonやPATHは変更しません。

保存先は設定ディレクトリーの`runtimes/<部品>-<版>-<hash先頭>`です。既定は`%LOCALAPPDATA%\TranscriptionServer\runtimes`。ユーザーPATH、System32、既存のプログラムフォルダーは変更しません。ZIP内のライセンス等も保持します。中止・失敗した所有一時フォルダーは破棄し、既存完成品は上書きしません。

## 反映と表示

- v0.1.12の実行環境は「導入済み・反映中」を経てそのまま利用可能になります。反映済みの環境に再起動通知は出しません。公開v0.1.11以前の再起動待ち通知とは区別します。
- 「サーバーを再起動」で専用確認画面を開き、確認後にサーバーだけを再起動します。処理・待機・転送・モデル操作・更新中はボタンを無効化し、APIでも拒否します。空き状態なら、同PCまたは既存の信頼LAN認証から操作できます。Bearerモードの別PCからの再起動は拒否します。
- 録音・字幕・設定・保存先・待受/許可ネットワーク・PID記録の指定を引き継ぎます。旧プロセスとモデル/DBの終了後に同じEXEを起動し直し、管理画面はPID変更と接続回復を確認します。常駐モデルは解放され、必要に応じて再ロードしてください。
- 次回起動時に専用実行環境を検出します。有効な明示パスは維持し、未指定または消失した明示パスでは専用領域を参照します。設定JSONやCLI引数は自動で書き換えません。
- モデル重みがない場合は「モデル未導入」。実行環境欠落、媒体変換の不足、起動点検失敗、対応モデルなしと区別します。未対応モデルへ導入成功を表示しません。
- Whisper専用環境も管理画面から導入できます。固定の公式Python/PyPIアーカイブのSHA256を照合し、依存DLLは採用済み公式NVIDIA配布ZIPから専用領域だけへ配置します。任意パッケージやpipは実行しません。GPUドライバー/OSライブラリーやWhisperのSM5.2不足も、この取得ボタンで解消した扱いにしません。

## API

### 一括モデル管理と行別通知

管理画面の「すべて導入」は未導入モデルと不足する管理対象実行環境を順に導入します。導入開始の確認は出しません。19GB一体型などの方針上の対象外、未対応、導入済みはスキップします。「すべて削除」は確認した一覧のモデル保存ファイルだけが対象です。ロード中のモデルは除外し、録音・結果・設定・実行環境は保持します。APIも既存の信頼LAN/操作トークン・受付排他を維持します。

```json
{"action":"install-all"}
{"action":"delete-all","confirm":"delete-all-models","models":["whisper/tiny","auxiliary/silero-vad"]}
```

対象IDは開始時に固定し、1件ずつ処理します。1件のエラーでは残りへ進み、中止要求では未処理分を実行しません。削除確認後に対象がロードされた等の状態変化があれば拒否します。単体操作との同時実行や処理・転送・更新中の操作はできません。

`GET /api/management`の`operation`には`targets`/`skipped`/`totalCount`/`completedCount`、現在の`model`/`targetLabel`と取得進捗が入り、`modelResults`にはモデルIDごとの今回プロセス内の最終操作結果が入ります。再起動すると操作結果表示はリセットします。進捗はダウンロードの実バイト数、取得CLIの実パーセント、Whisperワーカーの実カウンターを使用し、取得単位がファイル件数のときは明記します。取得元や旧ワーカーが通知しない場合、展開/起動点検中は不定進捗と表示します。転送量はMiBのままです。

進捗と再起動通知だけを画面上部へ固定し、完了・失敗は該当モデル行へ表示します。モデルの`restartRequired`は、重み導入済みで実行環境が反映待ちの場合にだけtrueです。モデル重みの取得だけでは再起動を要求しません。必要なモデル名・実行環境名を上部へ列挙し、各モデル行にも再起動を案内します。

`GET /api/management`へ`runtimes`、`restartRequired`、モデルごとの`managementState`/`statusMessage`/`missingRuntimes`を追加します。従来の`availability`、API protocol3と既存クライアント契約は維持します。

v0.1.12はhealth.capabilitiesの`automaticRuntimeSetup`/`runtimeStorage`と、managementの`runtimeSetup`/`runtimeStorage`を追加します。runtimeSetup.stateはcomplete/incomplete/disabled（初期化用not_runも使用）、resultsは環境IDごとのinstalled/reused/errorと失敗理由です。runtimeStorage.runtimesはIDごとのmeasuredBytes/capacityComplete/external/referenceInstalledBytes/referenceDownloadBytes、全体はtotalBytes/complete/unmeasuredRuntimeCount/measuredAt/basisと新規導入参考合計です。容量が未集計でも状態や参考値を実測と扱わないでください。既存runtimesと認識APIは維持します。

v0.1.5はhealth.capabilities.serverRestart=trueとmanagement.restartBlockedを追加。`POST /api/management/restart`、JSON `{"confirm":"restart-server"}`、既存の操作トークン/Bearer認証を使います。成功時はrestarting=true/previousProcessId、busy時409、不正確認400、認証/接続元不許可401/403。更新適用・停止APIの同PC限定は維持します。これは再起動の実装であり、Windowsサービス/自動起動の追加ではありません。

```json
{"action":"install-runtime","runtime":"speech"}
```

既存の`POST /api/management`に送ります。`runtime`は`whisper`/`speech`/`nemo`/`ffmpeg`だけです。任意URL・任意パス・任意コマンドは指定できません。進行中の中止は既存の`{"action":"cancel"}`、再点検は`{"action":"refresh"}`です。

配布元: [speech.cpp 0.10.1](https://github.com/nyosegawa/speech.cpp/releases/tag/v0.10.1)、[NeMo-Speech.cpp 0.3.0](https://github.com/NVIDIA/NeMo-Speech.cpp/releases/tag/v0.3.0)、[Gyan FFmpeg builds](https://www.gyan.dev/ffmpeg/builds/)、[FFmpeg SHA256](https://www.gyan.dev/ffmpeg/builds/packages/ffmpeg-8.1.2-essentials_build.zip.sha256)。

## 軽量配布と個別アプリ

v0.1.7以降のsetup/ZIPは本体・Web画面・資料だけです。モデル・FFmpeg・認識ランタイムは同梱しません。公開済みv0.1.11では管理画面から不足部品→モデルを導入します。v0.1.12は起動時に実行環境だけを準備し、モデル本体は利用者が導入します。ブラウザー内Whisperは利用アプリ側で管理し、本サーバーでは導入しません。

個別アプリは`--instance-id <固有ID> --local --host 127.0.0.1 --port <8769以外> --data-dir <絶対path> --settings-dir <絶対path> --process-record <絶対path> --no-browser`で起動します。`--installed`は使用しません。healthとPID記録のinstanceId/PID/開始時刻を照合し、その所有プロセスだけを管理します。非共有instanceはPATH上の認識ツールを暗黙使用せず、子プロセスのLOCALAPPDATA/APPDATA/HFキャッシュも専用設定先配下へ分離します。既存の共有データ/モデルは自動移行しません。

## v0.1.14作り直し版の初期モデルとおすすめ導入

実行環境の準備に続けて、Nemotron 3 Diarization、Silero VAD、Whisper Baseを順番に導入します。既に導入済みなら取得を省略します。初期モデルは保存のみで、メモリへ常駐ロードしません。準備中は認識受付を止め、既存の上部進捗・中止・行別結果を使用します。手動再起動は不要です。

設定フォルダーのinitial-models.jsonへモデルごとの成功を保存します。記録のない既存環境も次回の自動準備時に対象になります。失敗は次回起動で再試行しますが、初期導入に成功した後で管理者が削除したモデルを起動のたびに再取得しません。記録破損時は準備エラーとして報告し、成功扱い・自動初期化をしません。--no-auto-runtimesまたはauto_install_runtimes=falseならモデル自動取得も行いません。

上部の「おすすめモデルを導入」は精度重視のHaas-ja-v1.0とQwen3-ASR 1.7Bだけを対象にします（登録保存容量の合計目安2.84GB、実行環境は別）。未導入分を既存の導入手順で順次処理し、導入済みはスキップします。必要な実行環境は先に導入・反映します。確認ダイアログや常駐ロードは追加しません。処理・転送・更新中は操作できません。

API: GET /api/managementのrecommendedModelsで対象IDを通知し、POST /api/managementへ{"action":"install-recommended"}で開始します。サーバーが対象を固定し、クライアントの追加IDを導入対象へ広げません。

選定は、日本語向けHaasの公式評価と、多言語Qwen3-ASRの上位1.7B構成を参考にしたものです。量子化された本サーバー構成での優劣や、すべての録音での最高精度を保証するものではありません。

- https://github.com/QwenLM/Qwen3-ASR
